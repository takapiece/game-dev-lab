画面上には役割の異なる2種類のゲージが存在し、プレイヤーが迷わず操作できるよう段階的に改良されました。

下部固定

🛡️ 敵のディフェンス強度 (DEFENSE PRESSURE)

画面最下部に常駐。敵ディフェンダーとの距離や位置関係によってリアルタイムに増減し、シュートの成功率に直接影響します。画面下部に置くことで、中央のプレイ画面を邪魔しません。

4段階進化

🎯 シュートタイミングメーターの変遷

  1. ① 画面下（初期）: 敵プレッシャーバーと近く、プレイヤーの体と離れていて見づらかった。
  2. ② 画面上部（昼）: キャラクター被りを防ぐため上部へ移動。しかし視線が上下に激しく動く課題が発生。
  3. ③ 人物に追従（午後）: 縦型メーターにしてキャラクターの真横へ！視線移動ゼロで、選手の動きとメーターを同時に見られるように。
  4. ④ オン/オフ切替 [M]（完成）: 上級者や没入感を重視する人のため、キーひとつで非表示にできるハイド設定を追加。
GAME FEEL & CAMERA

🎬 カタルシスを生む「360度オービットカメラ」

「ただシュートが入って数字が増えるだけ」と「ゲームとして気持ちいい」の差は、カメラワークにあります。

シュート成功時（BUCKET!）にプレイヤーを一周

ボールがリングを通過した決定的な瞬間に、カメラが自動的にプレイヤーの周囲を滑らかに旋回（オービット）します。 これにより、成功した瞬間の達成感とドラマチックな余韻が生まれます。

💡 ゲーム開発のポイント: 通常プレイ中は操作しやすい「斜め俯瞰カメラ（クォータービュー）」を維持し、決定打の瞬間だけ「演出用カメラ」へスムーズに切り替えるのがプロの演出手法です。

🤖 AIへの指示書 (プロンプト) のリアル

プロのゲーム開発者がAIエージェント（Astra/LLM）に送った実際の指示書から、指示のコツを学びます。

❌ 失敗しやすい指示（曖昧・丸投げ）
「3DのバスケゲームをUnityで作ってください。
かっこいいキャラクターと敵AIもつけて、
シュートが入るようにしてください。」

👉 AIが勝手に複雑な仕組みを作り、どこでバグが起きたか分からなくなる。

⭕ 実際に使ったプロンプトの抜粋（ASTRA_BRIEF.md より）
「G0では素材統合を行わない。
プレースホルダー（CubeとSphere）だけで、
① 放物線軌道とリング通過の物理判定
② タイミング評価（Green Release）と実際の物理判定の分離
を成立させ、テストが合格するまで人型モデルを入れてはならない。」

👉 制約（やってはいけないこと）と合格条件を明確にすることで、AIがブレずに動く核を作る。

💡 生徒が今日から使えるプロンプトの3原則

1 やってはいけない制約を書く

「まだキャラクターは入れない」「外部アセットは使わない」など、AIの先走りを止める。

2 合格条件（受入基準）を数値で示す

「シュートが3本入ったら次のコートへ進む」「エラー0件でビルド成功」など客観的な基準を示す。

3 失敗したらエラー文をそのまま渡す

「動かない」ではなく、Unityコンソールに出たエラー全文とログを渡して原因を分析させる。

⚖️ Three.js (GAME 01) vs Unity (GAME 02)

同じ「3Dバスケットボール」を2つの技術で作ることで、それぞれの特徴と選び方を理解します。

比較項目 🏀 GAME 01: Three.js (JavaScript) 🌍 GAME 02: Unity (C#)
開発スタイル コードだけで画面を構築（HTML/JS） ビジュアルエディタ（Scene）＋ C#スクリプト
物理エンジン 自前計算 または Cannon.js（軽量） PhysX（高精度なリジッドボディ・コライダー）
アニメーション プログラムによる座標移動や簡易ボーン Mecanim（Humanoidボーン、ステートマシン）
起動・配信速度 ⚡ 一瞬（Webページを開くだけ、容量数MB） ⏳ 初回ロード約50MB（WebGLエンジン展開）
得意なこと Web上でサクサク動く学習教材、プロトタイピング リッチな3Dグラフィック、スマホアプリ・Steam公開

📜 アセットの権利とCC0ライセンス

「無料だから使っていい」は大間違い！クリエイターとして絶対に知っておくべき素材のルール。

⚠️ プロの開発現場での教訓（ASSET_SOURCES.md より）

「Unity Asset Storeで無料配布されている素材でも、AIへの入力や改変、プロジェクト外での再配布がEULAで禁止されている場合があります。『無料の価格表示』と『自由に使って良い権利』は全く別物です。」

✅ CC0 (パブリックドメイン)

作者が著作権を放棄した素材。商用利用・改変・AI利用も原則自由。本プロジェクトの人物モデルや一部背景に採用。

🔍 Unity Standard EULA

Asset Store素材の標準規約。Unity外へのエクスポートや、素材自体の再配布は禁止。注意深い確認が必要。

商用利用の可否や学習元の権利がプラットフォームごとに異なる。台帳（ASSET_SOURCES.md）を作り、出典を1つずつ記録する。

🐛 トラブル解決（デバッグ）の思考プロセス

AIと開発中に実際に起きたリアルなエラーと、それをどう解決したかの実例（ERROR_LOG.md より）。

事例 1: 物理のすり抜け

ボールが高速で飛ぶと、リングのコライダーをすり抜けてしまう

【原因】: Unityの標準物理判定（Discrete: 離散的）では、フレーム間の移動量がリングの厚みを超えると衝突を検知できない。

【AIとの解決法】: ボールの Rigidbody の Collision Detection を Continuous Dynamic に変更し、さらにリング上部にトリガーゾーンを設けて多重判定を行う二重防御を実装。

事例 2: WebGLビルドでの音の遅延

ブラウザ（itch.io）で起動した際、シュート音が遅れたり鳴らなかったりする

【原因】: ブラウザの「ユーザー操作前の自動音声再生禁止（Autoplay Policy）」および圧縮音声のデコード待ち。

【AIとの解決法】: 初回タッチ時にオーディオコンテキストをアンロックし、効果音のロード設定を Decompress On Load に固定して即時発音を担保。
