# Astraへの制作指示書

版1.0 / 2026-09-20 / 対象：このフォルダを操作できるローカルAstra/Codex

## 0. あなたの任務

既存アセットを活用して、Unity製3Dバスケット **HOOPS: WORLD TOUR（仮称）** を完成させてください。今回は授業用の小刻みな教材制作ではなく、短時間で人に見せられる作品を作るチャレンジです。教材への分解、Blenderでの本格的な独自化は後段です。

仕様の正本は `docs/00_roadmap/REQUIREMENTS.md`。判断経緯は `PROJECT_PROPOSAL.md` と `REVIEW_DECISIONS.md`。この指示書は要件の要約と作業手順であり、別の仕様を作る場所ではありません。

## 1. 最初に読むもの

このフォルダのREADME.md、HANDOFF.md、要件、精査記録、アセット台帳、技術設計、受入試験を読んでください。上位の適用可能なAGENTS.md / GEMINI.md / 既存Skill・締め作業手順があれば確認し、このプロジェクトの差分だけを適用してください。新しいグローバルルールを勝手に作らないでください。

兄弟の `../01_hoops_3d/` は保護対象です。必要なら指定された資料を読み取り参照しますが、ソース・教材・共通ポータルを変更しないでください。既存の資格情報を探索・表示しないでください。

## 2. 成果物の約束

攻撃プレイヤー1名と守備CPU1名。自動ドリブル、Spaceの長押し・解放によるシュート、入力タイミングと守備圧、物理ボール、正しい得点、各3本成功、Street→Gym→Arena→Neon、結果画面と再プレイを実装します。

初版の完成品は4世界を通して遊べるWindows x64ビルドです。1コートは大切なチェックポイントですが、4世界完成と報告してはいけません。CPUは攻撃しないため「完全な1on1」と宣伝しないでください。

人物は既存の使用条件を確認した素材を最優先。初期動作確認でCapsuleを使っても構いませんが、G2以降には人型とシュート・ドリブルの対応が必要です。素材生成OSSの新規セットアップ、オンライン、課金、5v5、ロスター等へ広げないでください。

## 3. 権限と費用

追加支出の予算は0円。素材購入、有料API、クラウドGPU、Unity AI有料機能、プラン変更、リセット購入を行わないでください。既存の利用枠・リセットの有無は画面で確認できる場合に限り記録し、リセットの確定操作はTakaに任せてください。

Asset Store素材は無料表示だけで採用しないでください。独自EULA、一般規約のAI入力に関する条項、ソース再配布条件を確認します。条件が未解決なら素材をAIへ入力せず、CC0または自作へ切り替えて続けてください。無料素材の非公式転載サイトは使いません。

公開、Git push、Driveの一般公開共有、SNS投稿は実行しません。外部ツールの認証、契約、保護機能の回避もしません。購入・破壊的変更・権利不明・新たなアカウント認証が必要な処理だけを停止し、依存しない作業は進めます。

## 4. G0：実機の事前確認

1. 作業ルートとGitの状態を確認。既存リポジトリ内に無断で別の.gitを作らない。既存変更を上書きしない。
2. OS、CPU/GPU、RAM、空き容量、Unity Editorの実行ファイル、Windowsビルド支援、ライセンス、URP等の互換を確認し記録する。
3. Unity操作手段を確認する。既に使えるCLI/MCP/エディター連携があれば使う。なければEditorスクリプトと通常のbatchmodeを検証する。特定のポート、独自CLI、外部サービスの存在を決め打ちしない。
4. 最小シーンを作り、コンパイル→起動→Windowsビルド→単体実行まで通す。自動化が見えているだけで成功としない。
5. Drive同期下での作業コピー・Library等の扱いを確認し、同期競合を避ける。同期方式や保存場所の大幅変更は提案に留める。

操作用の画面取得・入力ツールがなければ、その制約を明記します。コードの静的検査や自動テストを行っただけで「自分で実プレイした」と報告しないでください。

## 5. 実装の進め方

**G1：共通コア。** 単一コートで移動、守備、ドリブル、投球、得点、3本成功、リトライを完成させる。球・リングの衝突形状は外観モデルから独立させる。

**G2：見せられるStreet。** 利用条件確認済み人型と基本モーションを導入。Streetの背景、カメラ、音、最小VFXを整える。手と球のリリースを合わせ、Windowsビルドを保存する。

**G3：4世界。** 同じGameplayRootの上でGym、Arena、Neonへ環境を差し替える。データと進行の再初期化、最後の結果、再プレイを確認する。世界ごとに別のゲームロジックを作らない。

**G4：公開候補。** 受入試験を実施し、重大障害を修正。素材台帳とREADME、既知の制限、実プレイ録画、配布用ZIPを整える。公開はせず、確認用に提出する。

各ゲートで「実行ファイルが存在する」だけでなく、起動と代表操作を確認してください。成功した版を上書きせず残します。同じエラーへの無根拠な再試行は2回までを目安とし、再現と原因の切り分け、代替案へ移ります。

## 6. 実装上の重要ガード

- ボールの制御者は一つ。保持中のTransform/kinematic制御と飛行中のDynamic物理を競合させない。
- Greenは入力評価であって得点ではない。得点は実際の下降通過とshotIdで一度だけ確定する。
- リングを単一の凸MeshColliderにして穴を埋めない。見た目の線にも自動で衝突判定が付くとは考えない。
- Spaceのジャンプ・シュートの二重割当、Root Motionと移動コードの二重実行を防ぐ。
- 全ワールドで球とゴールの縮尺、得点面、プレイ領域を共通にする。
- フォーカス喪失、一時停止、シーン切替、Rでの再開始はチャージや投球イベントを安全に取り消す。
- 2026-09-20のユーザー指示により、静止時スティール・ジャンプシュート・近距離ダンク・得点時のジャンプと回り込みカメラをStreetで先に整える。敵の2倍ダッシュは入れない。その後に4世界へ進む。オンライン、リプレイは対象外。
- 仕様・美観・難易度を勝手に大幅変更しない。日常的な数値調整は理由と結果を記録して進める。

## 7. 記録と再開

大きな区切りごとに `docs/01_sessions/DEVLOG.md` とHANDOFF.mdを更新。設計変更はREVIEW_DECISIONS.md、エラーはERROR_LOG.md、素材はASSET_SOURCES.md、試験結果はACCEPTANCE_TESTS.mdの記録先に追記してください。似た役割の新規ファイルを乱立させないでください。

残量や期限が不明でもチェックポイントは保存します。制限到達後の自動継続を約束せず、再開時には実在ファイル・Git差分・最後の合格ビルドを再確認してください。

提出時には、最新の合格ゲート、変更点、実行手順、実際のテスト結果、未実施項目、利用した素材、残課題、人間の確認が必要な点を短くまとめます。実測していないfps、制作時間、費用削減、成功率は作りません。
