# 4世界と衣装の切り替え

ユーザーの「ステージへ進む・コスチュームチェンジ・次に効果音と音楽」に対応。今回の対象は4環境と衣装・進行であり、音楽制作は次の工程とする。最新ビルドと検証結果は[HANDOFF](../../HANDOFF.md)を参照。

## 操作と完成した流れ

Street→Gym→Arena→Neon。各3本の実得点後、喜びのカメラ演出が終わると「NEXT」ボタンまたはEnterで次へ進める。自動的に次へ飛ばさない。

Rは今のコートの記録だけを取り消してやり直す。Neonの結果で全体再プレイを選ぶとStreetと通算0へ戻る。「TITLE」も全体を初期化する。最後は通算成功・試投・命中率を表示し、0試投は数値を出さない。

タイトル/PauseのOUTFITボタンでAUTO、STREET、TRAINING、HOME TEAM、NIGHT RUNを循環選択。AUTOはステージに連動し、敵は常にステージ連動。既存人物モデルのシャツ・パンツ・靴の配色と、自作の頭の帯を切り替える。新しい衣服メッシュや身体モデルを導入したものではない。足元の輪は攻撃と守備の識別色を維持。能力や当たり判定は変えない。

## 実装の手順

1. G3WorldBuildでEnvironmentRoot下に4環境を生成。Streetは元の街並み、Gymは高窓・梁・ベンチと木床、Arenaは段状の観客席、Neonは夜景と光るフレーム。外部素材の追加取得はない。
2. HoopsWorldsに環境・床の材質・光の設定をまとめ、一つだけを有効化する。人物・物理床・リング・球・カメラは共有する。
3. HoopsGameが世界番号とクリア済み試投数を管理。現在のコートの結果を足して通算を表示する。次へはクリアと演出終了の両方を確認する。
4. 切り替え前にカメラの遮蔽物を復元し、Renderer一覧のキャッシュを捨てる。次の環境で再取得し、前の環境だけを参照し続ける不具合を避ける。
5. 衣装は保存済みMaterialと頭の骨に追従するメッシュで切り替える。既存モーション・ボールの制御者は増やさない。
6. Build-Checkpoint.ps1でg3の未使用番号を指定し、worldを含む検証を実行。成果物の上書きをせずソースZIP・ログ・ハッシュ・画像を残す。

## 検証の範囲

world検証は得点メソッドへ直接成功を注入せず、通常のチャージ/解放と下降通過で12本を決める。完走条件の検査では守備を止め100％幅にして確実な投球条件を用い、標準45％・守備ありで人間が完走した証拠とは区別する。各世界で描画・衣装・一回転の4方向を保存し、現在コートの再試行、全体再プレイ、設定維持、球/人物/AudioListenerの重複なしを確認する。既存runtime/actions/camera/orbit/visualも回帰確認する。

## 💡 このセッションで学んだプログラミング概念

- データと処理の分離：世界が増えても得点のプログラムを4コピーしない。外観の参照だけを差し替える。
- 状態遷移：クリアと演出終了は別。両方が揃ってから次の操作を許可する。
- 集計範囲：現在コートのやり直しと全体のやり直しを分けると、通算成績を正しく取り消せる。
- キャッシュの寿命：環境を交換したら、カメラが記憶した描画物の一覧も更新する。
- 観測と保証：自動試験の成功だけでは、文字の大きさや装飾の食い込みは分からない。画像も確認して直す。
