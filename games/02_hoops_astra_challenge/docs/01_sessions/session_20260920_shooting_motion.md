# 45％非表示と人物動作の実装記録

ユーザー承認に沿い、シュートの基準→プレーヤー→敵の順で実装。最終版はG2-12。既存教材とは独立したこのゲームの記録。

## 手順と成果

1. 標準を45％・非表示に変更。0.28～0.82秒が良い入力時間。幅調整・M/表示ボタン・100％を保持。
2. G2-08で距離2/4.5/7.5m、早/良/遅、フリー/正面守備の実物理比較を記録。フリーへの新しい乱数は加えず、守備の効果を確認。
3. 球が構えに達する時点を許容時間の入口へ合わせ、SET / RELEASEを表示。始動・停止・反転・加速に0.24秒の荷重を追加。
4. Pauseで腰が戻る不具合を新検査で発見し、Animatorも停止/再開する処理を追加。G2-10で確認。
5. 敵を近距離で低い構え、遠距離で追走、見えたシュートに反応して片手を上げる姿勢へ。移動速度・守備圧は維持。
6. ユーザーが停止中の歩行を指摘。停止時と移動命令欠落時の待機復帰を修正し、両者のClipと足変位を回帰検査。

再ビルドはBuild-Checkpoint.ps1へ実在のEditorPath、既存ScratchPath、未使用のg2日付番号、Reviewsを渡す。環境依存の実パスはEvidence内のローカル記録を参照。先に動いているUnityが同じ検証コピーを開いていないか確認する。既存チェックポイントは上書きしない。

## 学んだプログラミング概念

- 表示と判定の分離：バーを隠してもタイミング判定は同じ。許容時間幅と成功確率は異なる。
- 状態と連続更新：補間値は、更新処理が来なくなった場合に中間値が残る。移動の開始だけでなく終了・命令欠落を設計する。
- 複数のアニメ制御の調停：Animatorと手続き的IKを使う場合、Pauseで両方が同じ状態を保つ必要がある。
- 検証対象の選択：足だけの停止検査では腰の姿勢変化を見逃す。動いている脚の試験だけでは停止後の歩行残りを見逃す。
