# エラーログ

初期書類作成時点では実機エラーなし。2026-09-20のG0検証結果を以下に追記。

## ERR-G0-001｜制限環境でUnity初期化が止まる

- 現象：`CreateDirectory ... Unity/Caches failed: アクセスが拒否されました`、ライセンスIPC接続拒否。ビルドは未開始。
- 対応：今回起動したUnityを終了し、権限確認を経て通常ユーザー環境で再実行。既存ライセンスのentitlement解決を確認し、ビルドまで進行。購入・再認証・保護機能変更なし。
- 証拠：`../../Evidence/g0-20260920-01/editor-sandbox-failed.log`。個人パスを含む内部ログ。
- 学び：インストール不足とサンドボックスの実行制約を区別する。GUIアプリの起動コマンドが戻っただけで終了コードを判定せず、Start-Processでプロセス終了を待つ。

## ERR-G0-002｜ProjectVersion.txt欠落とパッケージ自動補完

- 現象：テンプレートの設定抽出後、版情報が欠けた状態で初期化し、不要な既定パッケージが追加された。
- 原因範囲：ProjectVersion.txt未作成と追加されたmanifestを実際に確認。内部の自動補完条件までは断定しない。
- 対応：自分が起動したEditorを停止し、6000.6.2f1と必要なURP・モジュールだけのmanifestを明記。再実行で意図したmanifestが維持され、ビルド成功。
- 証拠：G0-01のeditor-version-unset.log、固定ソースのmanifest/lock/ProjectVersion。
- 学び：エンジン版とパッケージ版を最初に固定する。

## ERR-G0-003｜非表示ウィンドウでPNGが黒い

- 現象：G0-01はプロセス終了0、状態遷移とPNG生成成功だが、AIが画像を開くと黒一色。旧smoke-result.jsonのpassedは描画成功を意味しない。
- 対応：G0-02で画像の輝度差を検査。実操作用の通常ウィンドウへ切り替え、タイトル・床・立体の描画を画像確認。画面入力は人間に依頼。
- 原因範囲：非表示起動時のキャプチャで再現し、通常表示時は描画。GPU自体の不具合とは判断しない。
- 証拠：両Build IDのtitle.pngとVALIDATION.md。
- 学び：画像ファイルの存在だけで描画成功を判定しない。

## WARN-G0-004｜未使用ポストプロセスのShader stripping警告

## ERR-G1-001｜遠距離・粗い物理刻みで良タイミング投球が入らない

- 初版g1-20260920-01：58件中54成功、T07遠距離3地点とT11粗い物理刻みの1件が失敗。ビルド自体はエラー0。

- 再試験：g1-20260920-02で同じ58件すべて成功。9地点の実剛体投球、リング・板・床衝突、1/30秒物理刻みも合格。runtime-tests.jsonを各Build IDのEvidenceに保存。

## ERR-G2-001｜腕を伸ばす場面で球が手から離れる

- G2-01の描画確認でPending時の右手と球中心が約0.27m、リング真下のChargingで約0.37m離れていた。球半径0.12mを考慮しても保持中の隙間がある。自動試験110件と描画の黒画面検査だけでは美観不具合を検出できなかった。
- 原因：固定1.95mの発射位置と、近距離で水平0.65m離した保持位置がリグの腕の可動範囲を超えていた。
- 修正方針：発射高さ1.8m、チャージ高さを1.63mまでに制限、足を固定したまま骨の重心を球側へ最大0.23m寄せる。投球後の物理は補正しない。
- 確認：G2-02で既存110件を再試験し、画像確認に保持中の右手から球中心まで0.22m未満の検査を追加。結果は対応Build IDのVALIDATION.md。
- 学び：IKは腕の長さ以上には伸びない。見た目の手と物理の発射位置を同じ座標に指定しただけでは一致を保証できない。

## ERR-G2-002｜移動アニメが1回で止まる

- きっかけ：ユーザーが走るモーションの必要性を指摘。従来の確認は短い場面画像が中心で、繰り返し再生の検証が不足していた。
- 診断：Unity上の実クリップを検査したところ、Idle/Walk/Run/Run_Left/Run_Right/Run_Backの全6種がisLooping=false。Animations.fbx.metaのclipAnimationsも空だった。証拠はG2-03のanimation-before.json。
- 原因：最初のコントローラー作成時にインポート済みAnimationClipへ行った一時的な設定が、ModelImporterの.metaへ保存されていなかった。既存コントローラーがある再ビルドではその処理自体も通らない。
- 修正：ModelImporter.clipAnimationsへloopTime/loopPoseを設定して再インポート。原本FBXは変更しない。方向別クリップを使うコントローラーを生成し、通常移動は進行方向、シュート中はゴール、守備は相手へ向ける。
- 検証：4秒継続する歩行・通常移動・走行・守備の骨座標を記録し、開始2秒以降の2区間でも足の動きが残るか確認する。結果は対応Build IDのmotion-review.json。従来110項目の合格だけではこの欠陥を発見できなかった。
- 学び：クリップが存在すること、最初の姿勢が見えること、継続して自然に再生されることは別の確認事項。

## ERR-G2-005｜停止中に歩くアニメが残る

- 現象：ユーザーがG2-11のデモで、座標が止まっているのに歩く動きを指摘。
- 原因：HoopsActor.Move内のSetFloat(..., dampTime, delta)だけでブレンドを更新しており、デモがMoveを止めると中間の値が残る。停止を1回だけ通知した場合も減衰が完了せず、通常停止でも短い歩行の残りが出る。
- 修正：MoveSpeedが停止域ならSpeed/MoveX/MoveZをゼロへ戻す。移動命令が来なくなった場合も、2フレーム目で速度をゼロとし待機に戻す。足の制動姿勢は別の0.24秒の補正で維持する。
- 検証：両者の明示停止/命令途切れについてIdle Clipのみになること、停止後0.4秒間の足の変位が6cm未満、ルート不動を検査。結果はG2-12以降に保存。
- 学び：アニメのパラメータは目標値を一度設定すれば自動で収束するとは限らない。継続移動のループ確認に加え、「もう命令が来ない」経路と停止後の骨の動きを試す。
追加検証：G2-12はruntime 131件/motion 40件とvisual/meterが全て成功。停止後の足変位は両者1cm未満で、明示停止・命令途切れともIdle Clipのみへ復帰。

## ERR-G2-008｜得点直後のカメラ注視点が急移動

- 現象：G2-17の4:3・コート端で得点した直後、カメラの1フレーム移動が最大1.652mとなり、上限0.9mの検査に失敗。人物と球の収容・操作軸は合格。
