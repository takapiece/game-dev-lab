# 要件定義書｜HOOPS: WORLD TOUR v0.1

版1.13 / 2026-09-20 / スマホ操作とローカルWebGL試遊への着手を反映。実装状況と実機試験結果はHANDOFFとEvidenceを参照。Word版はv1.6で未同期、実装正本は本Markdown。

## 1. 適用範囲と優先順位

本書は「先に完成品を作り、SNS公開と後日の教材化につなげる」チャレンジの実装基準。初版は攻撃側固定のバスケゲームであり、正式競技の完全なルール再現、CPU攻撃を含む試合シミュレーターではない。

**優先順位：起動と完走 → 操作・得点の正しさ → 人物とバスケ動作 → Streetの見栄え → 4世界 → 音・演出の調整 → 追加機能。**

| 区分 | 初版の扱い |
|---|---|
| MUST | Windows x64、攻撃1人＋守備CPU1人、4世界、各3本成功、結果・再開、人型、ドリブル、ジャンプシュート、近距離ダンク、静止時スティール、音・基本演出 |
| SHOULD | 守備の圧力表示、簡単な品質切替、撮影用HUD非表示、丁寧なワールドカード |
| LATER | レイアップ、ON-FIRE、リプレイ、ブロック専用アニメ、歩くポータル、アプリストア配信 |
| OUT | CPU攻撃、攻守交代、リバウンド争奪、パス、2v2/5v5、オンライン、課金、ロスター、セーブ |

2026-09-20のユーザー指示により、ダンクと静止時スティールをStreetの仕上げへ繰り上げた。旧版のLATER/OUT指定よりこの変更を優先する。4世界構成と各3本は維持する。

無料アセットは候補であり、本書への製品名の記載だけで採用済みにはならない。機能要件を守れる別の既存CC0素材への変更は許容し、台帳へ記録する。

2026-09-20追加：ユーザー承認により、横持ちスマホ操作→ローカルWebGL実機確認→調整後に公開先判断へ進む。左スティック・右長押し/解放シュート・ダンク・走行切替・Pauseを用意し、PC操作も保持。スマホで2本指同時操作、指のキャンセル、Pause/縦横切替で入力残留がないことを確認する。Webは30fps目標、実機品質の合格は測定後に判断。ローカル/LAN試遊までが今回の範囲で、外部公開・新規サーバー契約はしない。[計画](MOBILE_WEB_PLAN.md)。

## 2. 製品・画面フロー

タイトル／開始 → Street → クリアカード → Gym → クリアカード → Arena → クリアカード → Neon → 全体結果 → 再プレイまたはタイトル。

各世界は成功3本でクリア。成功1本を進行上の1点とする。2点・3点の競技得点、24秒ルール、時間切れ負けは初版に入れない。失敗回数や所要時間は結果として表示できるが、ゲーム進行を詰まらせない。

クリアカードでは操作を止め、「次へ」の明示操作で移動する。Neon終了後は通算成功数、試投数、命中率を表示。0試投の命中率は「—」とし、ゼロ除算しない。

3本目の喜びとカメラ演出が終わってからボタンまたはEnterで次へ進む。Rは現在のコートだけを再開始し、そのコートの成功・試投を取り消す。前のクリア済みコートの記録は維持する。最後の「全体再プレイ」はStreetと通算0から開始。「タイトル」も全体を初期化する。メーターと衣装の選択はアプリ実行中の再開始で維持し、保存・解放条件・課金は追加しない。

## 3. 操作とキャラクター

| ID | 要件 | 受入条件 |
|---|---|---|
| IN-01 | WASDで移動、Shiftで走る | 斜めだけ速くならず、コート外へ出ない |
| IN-02 | Spaceを押してチャージ、離してジャンプシュート | 1回の押下・解放で投球は1回だけ |
| IN-03 | ゴールへの基本オートエイム | 射程外・無効状態では投げず、理由を表示 |
| IN-04 | Escで一時停止、Rで現在のコートを再開始 | 再開時の押しっぱなし入力で勝手に投げない |
| IN-05 | ウィンドウのフォーカス喪失で安全停止 | チャージを解除し、復帰後は再押下が必要 |
| IN-06 | リング正面の1.35m以内でEキーのダンク | 遠方・背面・空中・演出中は発火せず、実下降通過で一度だけ加点 |
| CH-01 | 同じ基体でも識別できる2名の人型 | 攻撃・守備の配色と足元表示を区別 |
| CH-02 | Idle、移動、ドリブル、シュート、守備姿勢 | 腕とボールの動作に明確な対応がある |
| CH-03 | 衣装のステージ連動と手動切替 | 同じモデルのシャツ・パンツ・靴の配色とヘッドバンドで4種。タイトル/PauseでAUTO→Street→Training→Home Team→Night Runを選択。敵はステージ連動、足元の識別色と能力は維持 |

Starter Assetsを採る場合、Spaceのジャンプ割当とシュート割当の衝突を除く。キャラクター移動方式は一つに統一する。Root Motionとスクリプト移動で二重に動かさない。

初版のジャンプはシュートアニメーション内の表現とする。リングの真下（水平0.65m内）では球を外側へ避ける方向へ身体も向け、中心ではコート側へ向き直る。左右で十分な間隔があるときはゴールを向く。構えたまま真下へ入る経路でも腕だけを背中へ伸ばさない。Space解放時に踏み切り、約0.16秒後の空中の手位置から投球する。約0.56秒で着地し、空中の移動・再投球は止める。独立ジャンプキーは追加しない。既存の歩行・走行は利用し、不足するバスケ動作は短いポーズ補間またはクリップで補う。単に走行モデルを貼り付けただけの状態を「人型完成」と判定しない。

得点時は短い喜びのポーズを付ける。通常成功は片手、3本成功のクリアは両手で、ジャンプしてガッツポーズをする。通常2.6秒・クリア3秒、その間は両者の移動・守備・新投球を停止する。ダンク中の得点では先に着地してから喜ぶ。失敗では発火せず、Pause中は姿勢と時間を止める。Rは演出も初期化する。演出完了後に球と操作を復帰し、押しっぱなしのSpaceでは投げない。

### カメラ

通常プレイは従来より少し低く近い斜め後方から追従する第三者視点とし、操作人物・敵・ボール・ゴールが同時に読める構図を優先する。水平角度を固定し、WASDの方向はそのカメラの地面上の前後左右と整合させる。自由マウス視点は必須にしない。

シュート中は球とリングへ滑らかに注視点を移し、弾道に合わせて引いて両者を画面内に保つ。成功時は人物へ大胆に寄り、操作停止中に周囲を一方向へ360度回ってから、コート全体が見える元の角度と距離へ引く。再開時の操作軸を変えない。演出中に人物を隠す支柱・背景・成功球などは一時的に描画を外し、終了とRで戻す。クリアの結果操作は喜びと着地の完了後に表示する。結果表示は下部へ置き、中央の演出を見せる。Pause中はカメラも止め、Rで通常状態へ戻す。自動演出が操作を邪魔する場合は固定寄りへ戻す。4世界の壁や梁が視界を遮らないことを確認する。

## 4. ボール・シュート・得点

### 状態と責任

ボール状態は Held / Dribbling / ShotPending / Flying / Resolved / Resetting を基本とする。同時に複数の方式で位置を制御しない。

保持・ドリブル中は制御された軌道を使い、床より下へ沈ませない。シュート時は親子付けを解除し、Dynamic Rigidbodyに切り替えた後、計算した初速を一度だけ設定する。飛行中は通常の位置更新を物理へ任せる。[S12][S13]

ダンクはEキーで踏み切り、前方移動と上昇を同時に始め、約0.48秒でリング上から下向きに放す。横移動はCharacterControllerで行い、前へ進んだ位置に着地する。身体・手・球を一緒に進め、球がリングを越える高さになるまでは穴の外側を通す。発射後はDynamic物理だけを使う。タイミング判定は行わず、守備圧による初速のぶれを残す。約0.85秒で着地。背面や射程外では通常シュートを使う。

Inputの解放時にタイミング判定を確定し、投球は手がボールを離すモーション時点で発火する。投球イベントの重複を防ぐ一意のshotIdを持つ。

### Green Releaseの意味

Greenは「入力が良いタイミングだった」という評価。**無条件のゴール保証ではない。** 初版では飛行中の磁力、隠れた瞬間移動、リング通過前の得点確定を行わない。

入力誤差と守備圧に応じて狙い点・初速へ誤差を与える。守備圧が高い場面の良い入力は「Good timing / Contested」のように区別する。理想入力と無守備で安定して入るよう調整するが、失敗を帳消しにして得点だけ増やさない。

シュートメーターはプレーヤー横の人物と同程度の高さの縦型とし、下から上へ進む。設定画面でグリーン幅を4～100％に調整でき、標準は全時間幅の45％（0.28～0.82秒）。10/45/100％のプリセットを保持する。幅45％は命中率45％を意味しない。グリーン区間の定義を表示・入力評価・タイミング誤差で共用する。100％は全入力時間を良い判定とし、タイミング由来の狙いのブレをゼロにする。守備圧と物理衝突は維持し、成功を保証しない。能力値の実装はこの変更に含めない。

メーターの表示はボタンまたはMキーで独立して切り替える。標準は非表示とし、人物が球を構えた姿勢と短い文字の合図から離す時点を読めるようにする。非表示だけでは難易度・弾道を変えない。100％＋非表示ではタイミング由来の誤差がない。幅の変更は開始前またはPause画面で行い、チャージ/投球待ち中は変更不可。Pauseの取消と入力復帰ルールは維持する。再開始では設定を保持し、アプリの次回起動は標準45％・非表示に戻す。

| ID | 要件 | 受入条件 |
|---|---|---|
| SH-01 | ボールは重力・床・バックボード・リングに反応 | 床抜けや板すり抜けが通常操作で再現しない |
| SH-02 | 縦メーターと入力評価・誤差が一致 | 同じ区間で判定。全域グリーンはタイミング誤差ゼロ、表示切替は判定に影響しない |
| SC-01 | 有効投球がリング内を上から下へ通過した時だけ加点 | 下から、横から、同じ球の再通過では加点しない |
| SC-02 | 1投球につき最大1得点 | イベント重複でもスコアが2回増えない |
| RS-01 | 成功・失敗・場外・停止球から自動復帰 | 手動でボールを取りに行かず次の投球が可能 |

得点は上下Triggerの入場順だけに依存しない。前後の物理ステップ間のリング面横切り、下降方向、リング内の位置、投球IDを合わせて検証する。薄いTriggerを高速で通過したケースも試験する。[S14]

復帰は解決表示の後に行い、通常は約1秒の演出間を置く。未解決の飛行には6秒の上限を置き、判定できない球が永久に残ることを防ぐ。これらは初期調整値であり、演出に合わせた変更を認める。

## 5. 守備CPU・難易度・寸法

### 守備の要件

CPUは通常、ボール保持者とゴールの間へ移動し、距離と正面方向から守備圧を計算する。リングから1.6m未満ではコート側に間隔を取って、真下の重なりや支柱奥への回り込みを避ける。到着時には停止し、球が飛んでいる間と結果表示中は追跡を止める。遠方の追走は進行方向、近距離の守備は相手へ身体を向ける。遠距離（3.7m超）は4.5m/sの通常走行、近距離は2.55m/sの守備移動。敵の2倍ダッシュ・追加加速は入れない。NavMeshや学習型AIの導入は必須にしない。

保持中のプレーヤーの実移動がほぼゼロで約3秒続くと、2.4m以内の敵が0.65秒の予備動作からスティールを仕掛ける。手を伸ばす動きと案内を表示し、移動で距離を取るか先に投球して回避できる。判定時に1.05m以内で保持中なら成功。成功は得点・試投を増やさず0.85秒で球を返す。CPU攻撃・攻守交代には移らない。再試行には2秒の間隔を置く。Pause/Rで状態を安全に扱う。

プレイヤーの未解放入力や未来の乱数結果を先読みせず、位置・距離・見えているシュート動作に反応する。瞬間移動、常時完全密着、逃げられない接触を禁止する。毎フレーム独立抽選で守備成功を決めず、時間間隔または投球単位で判断する。

v0.1はシュート妨害が主役。専用ブロック判定・叩き落としアニメが未実装なら「ブロック機能あり」と表示しない。

### 初期パラメータ案

以下は競技規則の引用ではなく、実装開始用の調整値。実機テストで変更したら設定と理由を保存する。

| 項目 | 初期値・方針 |
|---|---|
| 縮尺 | 1 Unity unitを1mとして制作 |
| プレイヤー高さ / 球の直径 | 約1.8m / 約0.24m |
| リング高さ / 内径 | 3.05m / 約0.45m |
| プレイ領域 | 幅約15m、奥行き約14m。背景は自由 |
| 歩行 / 走行 | 4.5m/s / 6.2m/s |
| 理想入力時間 / 良いタイミング幅 | 0.55秒 / 前後0.06秒を出発点とする |
| 最大チャージ | 1.2秒で自動リリース。メニュー・フォーカス喪失ではキャンセル |
| 世界ごとの守備速度倍率 | Street 0.85 / Gym 0.95 / Arena 1.05 / Neon 1.10 |
| 守備の反応遅延 | 0.20秒を起点。段階調整し、人間プレイで確認 |

前後左右と軸を統一し、ゴール位置は共通CourtRoot基準で管理する。アセットの寸法を変えて帳尻を合わせるのではなく、インポート時に実寸を確認して一度補正する。

4世界の初回確認版では、環境と衣装の比較のため守備速度は全世界で現行Streetと同じ4.5m/s・2.55m/sに統一する。上表の世界別倍率は将来の調整案として保留し、敵の2倍ダッシュは追加しない。

難易度を上げても4世界ともクリア可能な状態を維持する。「規定本数の成功」は計測結果ではなく、これから実装するゲームルールである。

## 6. ワールド・表示・音

| ID | 要件 | 完了条件 |
|---|---|---|
| WD-01 | Street / Gym / Arena / Neonの4環境 | 色だけでなくシルエット・主要構造の差が分かる |
| WD-02 | ゲームコアは共通 | 世界変更で得点・衝突ルールが別実装にならない |
| WD-03 | 世界の切替で正しく再初期化 | 人物・球・カメラ・音声リスナーが増殖しない |
| UI-01 | 世界名、成功0/3、縦型入力メーター、結果 | 人物横へ追従し画面内に収める。Mキー/ボタンでメーターだけを表示切替できる |
| AV-01 | バウンド、シュート成功、クリアの音 | 無音設定と音量調整が機能し、音源の利用条件を記録 |
| AV-02 | 良いタイミングと成功の演出を分離 | 入らなかったのに成功エフェクトを出さない |
| AV-03 | 得点時のジャンプ・ガッツポーズと回り込みカメラ | 演出中はプレイ停止。着地・視点復帰後に再開し、失敗時に喜ばない。Pause/Rを扱う |
| AV-04 | ステージBGMと独立した音量制御 | SE/BGMの別音量と一括ミュート、Pause/フォーカス喪失で停止し同じ位置から再開。R/全体再プレイは曲の先頭、タイトル/別世界では前のBGMを停止 |

ユーザー指定のBGMはStreet Take 1（177.60秒）、Gym Take 1（143.06秒）、Arena Take 2（179.52秒）、Neon Take 1（144.79秒）。原曲末尾を保った全体ループとし、音楽的に継ぎ目のない編集が済んだとは扱わない。標準BGM音量22％、SE音量35％を出発点とし、得点演出中はBGMを通常の55％へ下げて復帰させる。各世界に移ると選択曲の先頭から再生する。音量/ミュートは同じアプリ内の再開始で保持し、次回起動は標準へ戻す。

Streetは提供動画2本の音声を得点カメラ開始時に一度再生。1本目の2.4秒版を通常得点、2本目の2.8秒版を3本目のクリアに使用。失敗・入力のGOODだけでは歓声を鳴らさない。歓声はSE音量と一括ミュートに従い、Pauseで位置を保持、R/世界切替/タイトルで停止。ユーザー指定によりGymにも同じ通常/クリアの歓声を割り当てる。

全世界のボール音は提供動画の最初の衝撃だけを0.30秒へ切り出してドリブル/床接触に使用。リング音は0.63秒、ネット音は0.74秒。実入球でネット音を一度だけ再生する。ドリブルの1周期を音源内の複数ヒットで水増しせず、同種の衝突通知は75ms以内を一音へまとめる。異種の衝突は別に鳴らす。発射/成功/失敗の仮電子音は削除。板・支柱の専用素材は未提供のためボール衝撃音を暫定共用し、材質・世界ごとの音響差は今後調整する。

Arenaは専用の提供動画1本から2.4秒の歓声を採用し、通常得点/クリアで共用する。実得点カメラ開始時だけ再生し、SE音量・Pause/Mute/R/世界切替はStreetと共通の制御に従う。ユーザー指定によりNeonにも同じArena歓声を割り当てる。

初版の構成は一つのGameシーンにGameplayRootを保持し、EnvironmentRoot以下の4つの環境Prefabを差し替える方式を第一案とする。照明の都合で4シーン方式が簡単な場合は採用してよいが、共通コアはPrefab化し、どちらか一方式に統一する。

初版はリアルタイム照明中心、動的影を絞る。世界ごとの長時間ベイク、巨大な観客群、独自シェーダーの大量導入を必須にしない。演出用スローモーションは初版必須ではなく、追加する場合も入力評価や計測との整合を確認する。

2026-09-20の制作順は、4世界と衣装を先に確認し、その後に効果音・音楽を調整する。Streetは街並みとフェンス、Gymは木床・高窓・梁・ベンチ、Arenaは段状の観客席・看板・照明塔、Neonは夜景・光るフレームとする。初回は自作の簡易形状で区別し、新たな素材取得を必須にしない。

素材が使えない場合は環境の簡易自作へ切り替え、**4世界そのものを黙って削らない**。1世界だけで終了した場合は「中間版」と記録する。

## 7. 実行環境・品質・費用・公開

Unity 6系＋URPを基本とするが、パッチ番号、URP/Input System/Cinemachine等のパッケージ版はローカルで互換を確認して固定する。過去事例のバージョンやポート番号をそのまま採用しない。Cinemachine、MCP、Unity専用CLIは利用可能なら使うが、必須依存とはしない。

| ID | 非機能要件 |
|---|---|
| NF-01 | Windows x64の単体起動。ゲーム中に外部APIやネット接続を要求しない |
| NF-02 | 対象PCを記録。1080p・60fpsを目標とし、30fps未満が継続する場合は設定削減または要修正を明記 |
| NF-03 | 人物・球・UIが読める画面。スクリーンショットだけでなく連続プレイで確認 |
| NF-04 | 初版の追加支出0円。購入・有料生成・プラン変更・リセット購入は自動実行しない |
| NF-05 | 既存教材と上位ワークフローを変更しない。機密や絶対パスを公開ファイルへ含めない |
| NF-06 | Assets、Packages、ProjectSettingsと.metaを保全。Library、Temp、Logs等は配布対象外 |
| NF-07 | チェックポイントごとに実行ビルド、変更点、未解決事項、試験証拠を残す |
| NF-08 | 権利確認済み素材だけを公開成果物へ使用。素材入りソースと完成ゲームの配布を区別 |

Gitで除外してもDriveの同期対象から自動除外されるわけではない。Unityの作業コピーと再生成キャッシュを同期フォルダ内でどう扱うかはG0で確認し、複数PCから同時編集しない。

### 初版の出荷判定

G3は4世界を通して遊べること、G4はさらにACCEPTANCE_TESTSの必須項目が合格していること。重大障害、素材条件不明、得点の二重加算、終わらない状態がある場合は公開候補にしない。

Windows ZIPは実行ファイルとデータフォルダ・必要ランタイムをまとめ、Unity Editorを開かずに起動試験する。署名の有無は明記するが、OS保護を無効化する案内をしない。SNS投稿、外部公開、Git push、一般公開共有はTakaの確認後に別途行う。

本書作成時点では、PC性能・ライセンス・アセット取得・インポート・ビルド・全試験は未確認。出典と運用上の解釈は [ASSET_SOURCES.md](ASSET_SOURCES.md)、具体的な試験は [../03_architecture/ACCEPTANCE_TESTS.md](../03_architecture/ACCEPTANCE_TESTS.md) に集約する。
