# 精査結果・意思決定記録

2026-09-20 / 版1.0 / 文書と公式公開情報のレビュー。コード監査・実機試験の完了報告ではない。

## 1. 判定

**修正を反映した基準案で、制作へ進むための文書を保存してよい。** 重大な企画上の矛盾は、範囲・素材条件・完成の定義を整理することで解消できる。実行環境・アセット統合・実機品質についてはG0以降の検証が必要。

ユーザーの明示希望、アシスタントの設計提案、外部確認で分かったことを区別する。文書化は「すべての候補を取得し動かした」という意味ではない。

## 4. 開発開始時にのみ確定できる項目

PC性能、Unityの実行パス・パッチ、パッケージ版、Windowsビルド支援、利用資格、Astraの利用枠と期限、操作ツールの可用性、素材アーカイブ内のライセンス・無料収録範囲、実寸、リグとクリップ互換、実行時fps。

これらは「質問しないと文書が作れない」項目ではなく、制作エージェントがG0で実在を確認する項目。ただし契約・購入・認証など本人判断が必要な処理は代理で確定しない。

## 5. 情報の確度

外部価格・規約は2026-09-20の取得結果を整理した。更新日の表記や検索キャッシュが混在するため、導入当日にも製品ページと同梱ライセンスを確認する。OpenAIの利用枠の案内は公式検索結果本文を確認したが、元の簡潔なURLを直接取得する処理は失敗した。個人のアカウント残量・リセットは確認していない。[S02]

ライセンス欄は条文の存在と、この企画での保守的な採用判断を示すもの。個々の契約解釈を保証する法律意見ではない。疑義が残る素材を採用しなくても制作を進められる代替を用意する。

## 6. G0での決定（2026-09-20）

- C-013：Unity 6000.6.2f1 / URP 17.6.0 / Windows x64 / Mono / Direct3D11で最小アプリを検証。既存インストールでビルド成功。IL2CPP用の追加ツール導入は今回不要。ゲームの物理・表現仕様は変更しない。
- C-014：正本は既存フォルダのUnityProject。G0検証だけTEMPコピーを利用し、Library等をDriveへ戻さない。ユーザーはDrive同期を一時停止し、不具合が出たらDrive外の恒久作業場所を検討する方針を明示。恒久移動や同期設定変更は未実施。
- C-015：MCP追加導入を必須にせず、Editorスクリプト＋batchmodeを使用。ネイティブ画面入力手段がないため、ボタン操作は人間が行い、アプリの画像・イベントログを照合する。自動コールバック実行を実プレイと呼ばない。
- C-016：G0-01のPNG存在検査は黒画面を検出できなかった。G0-02は輝度差検査と人間の実操作確認を併用。G0-01を合格版にしない。

## 7. G1での決定（2026-09-20）

- C-017：G1は単一Streetコート。配布物のCC0人物1体と別ファイルの基本動作を使い、攻守の色を変える。バスケ動作は暫定IK。歩行Root Motionは無効、CharacterControllerに移動を統一。

- C-019：初速計算の最高点を距離依存にし、離散積分の半ステップ補正を初速に限って追加。SC-01/02の下降通過・有効半径・shotIdは変更なし。根拠はG1-01の4失敗→G1-02の同一58試験成功。
- C-020：自動試験は実Playerの物理と状態機械を使う。人間のキーボード入力・カメラ評価・難易度を置き換えたとは報告しない。試遊報告と記録を照合してG1を判定する。

## 8. 公式ルールの確認と近距離修正（2026-09-20）

- C-021：ユーザーの「リング下で打てないとフラストレーションになる」「主な公式ルールを把握して進めよう」を受け、暫定の最短距離1.5mを撤廃する。コート内のリング下・横・裏からも入力を受け付ける。最大8.5mは引き続きゲーム上の射程であり、競技規則ではない。
- C-022：参照基準はFIBA Official Basketball Rules 2024 v1.0a（2024-10-01施行）。2026-09-20に公式本文と配布一覧を確認。NBA等の別団体の規則と混同しない。本作は攻撃チャレンジであり、公式競技の完全再現とは称さない。

| 主な項目 | 公式規則の要点・条項 | 本作での扱い |
|---|---|---|
| 得点 | 上から入り、球が中に留まるか全体が通過する（16.1） | 開いたネットの下降通過を検出。球中心の侵入で仮判定し、全体の通過で確定、1投1回 |
| 下からの通過 | 球全体を下から通すと違反（16.2.4） | 無得点で試投終了。後で落ちてきても得点不可 |
| ゴール裏 | 後方という位置だけを禁止する規定ではない（16・23からの解釈） | 発射可能。ボードを避ける必要がある。自動で障害物を迂回しない |
| ボード・支柱 | ボード裏面・支持物への球の接触はアウト（23.1.2） | 裏面と支柱接触で無得点終了。前面や側面への接触だけではアウトにしない |
| 場外 | 境界線上・外の床などへの接触でアウト（23） | 人物は移動範囲内に制限。球はゲーム用の遠方境界と6秒で回収。空中で線を越すだけでアウトという公式規則ではない |
| ドリブル・足運び | 保持後の再ドリブルや、保持中の足の動きに制約（24・25） | 自動ドリブルとチャージ中の移動を許す簡略操作。正式なトラベリング等の判定は実装しない |
| 守備と接触 | 守備位置・接触・ゴールテンディング等を規定（31・33） | 位置による守備圧のみ。ファウル審判、球を叩くブロックなし |
| 得点配分・時間 | フリースロー1点、通常2/3点（16）、制限区域3秒等（26）、24秒（29） | 当初要件どおり成功本数で進行。競技の点数・時間制限は導入しない |

公式出典：[規則本文](https://assets.fiba.basketball/image/upload/documents-corporate-fiba-official-rules-2024-v10a.pdf)、[FIBA配布一覧](https://about.fiba.basketball/en/services/resource-hub/downloads)。条文の要約と本作独自の簡略化を上表で分ける。

- C-023：真下の発射は保持中の手位置をリング中心から水平0.65m以上離す。下から突き抜ける初期配置を避け、通常の放物線で狙う。球の飛行中補正はしない。近距離専用モーションはG2で整える。
- C-024：床に触れた後の球を無得点として回収する処理は、リバウンドを省く本作の簡略化。実際の競技で床に触れた球が常にデッドになるという説明はしない。球がリング内に留まった状態の審判判定も未実装。

- C-025（G2着手）：ユーザーがG1-03の近距離修正を確認。先の要望に沿ってStreetを昼の明るさへ調整し、チャージ中の膝のため、投球待ち0.16秒の腕の伸び、投球後のフォロースルーを加える。骨の姿勢だけを変え、CharacterControllerや飛行中の物理をアニメで上書きしない。購入・新規素材なし。
- C-026：見え方の確認は通常ウィンドウで自動の動作見本を描画し、複数場面の画像・骨位置・30fps制限での実描画間隔を保存する。人間の実入力や美観の合格と分ける。テストモード専用の`--g2-review`は完成品の通常操作には出さない。

- C-027：G2-01の描画・座標確認で手の到達不足を発見したため、発射高さを1.95mから1.8mへ調整。チャージの球高を最大1.63mにし、保持中は足を固定して骨の重心を最大0.23m移動する。初速は新しい発射位置から再計算し、飛行中補正・得点範囲の緩和は行わない。近距離0.65mの水平オフセットは維持する。

- C-028：G2で歩行/走行を先に仕上げるユーザー指示に従う。調査でループ設定の未保存を確認したため、インポート設定を正本として修正し、2秒以上経過しても足が動く実Player試験を追加する。以前の「組み込み済み」は継続再生を保証していなかった。
- C-029：移動速度4.5m/s、Shift6.2m/sは維持。通常移動はジョグ、Shiftは速い走り、低速時は歩行の混合。通常は進行方向、チャージ/投球待ちはゴール方向、守備は相手方向に向く。横・後ろのクリップも既存CC0パックのものを利用。静止中は直前の向きを維持し、照準時にゴールへ戻る。
- C-030：ドリブルの周期は移動速度に応じて変え、球が低い間は手を腰付近で待たせる。保持へ集める0.14秒、投球待ち0.16秒を位置補間し、球の瞬間移動を減らす。床で自作バウンド音を鳴らす。飛行中の物理と最終発射位置は維持。

- C-031：継続移動の画像で中央下の入力メーターが足元を隠すため、上部中央へ移動する。小見出しは短くして欠けを解消。クリア時には両者の移動ブレンドを止め、結果画面でその場走りを続けないようにする。

## 9. 動作調査と実装前の一覧化（2026-09-20）

- C-032：ユーザーの始動・停止・守備姿勢の提案を受け、追加実装前にFIBA/WABC Level 1の基本姿勢、守備の足運び、方向転換、停止を調査。[TECHNICAL_DESIGN](../03_architecture/TECHNICAL_DESIGN.md)に14項目の動作・切替条件・優先度・現状を記録。上部メーター位置はユーザーが「Good」と確認し、維持する。モーション全体の合格とは扱わない。
- C-033：攻撃は軽い準備姿勢から短く蹴り出し、停止時は足と膝で受ける。守備は低い基本姿勢を起点に横移動・追走・接近・シュートへの対応を切り替える。次の実装は基本姿勢と始動/停止を優先し、深いしゃがみを必須の待ち時間にしない。ルート移動、AI強度、投球待ち時間は維持し、体の補正を一元化して膝の曲げすぎを防ぐ。
- C-034：コーチ資料は動作の参考であり現行規則・配布用素材ではない。closeoutの足運びは接近制動の参考に留め、パスや新しい守備機能を追加しない。追加試験GM-01～06は未実施として登録。今回の成果は調査と設計記録で、ゲームコード・最新ビルドG2-04は変更なし。
- C-035：ユーザーの希望により実装順を「プレーヤー→敵」とする。先の攻守同時の基本姿勢整備案を更新し、プレーヤーの始動・停止・切り返しとドリブル/投球の接続を確認してから守備へ進む。方向キー2回押しで追加ダッシュし体力ゲージを消費する案は将来候補として記録のみ。今は実装せず、採用や数値・回復方式は未決定。既存Shift走行や必須要件は変更しない。
- C-036：ダッシュ操作・HUDは既存例を調査して比較するユーザー方針を反映。技術設計にInterface In Game、NBA 2K25公式説明書、Fortniteの導入時公式説明と確認範囲を記録した。Game UI Databaseは取得エラーのため未確認の候補。専用キー/切替/2回押しを誤発動・解除・同時操作で比較し、方式はまだ決めない。収録件数の宣伝文や静止画だけで操作仕様を確定しない。Windows先行・プレーヤー→敵・新ダッシュ実装保留を維持。
- C-037：ユーザーの「シュートのタイミングバーがスピード感を損なうかもしれない」を受け、プレーヤー工程の最初に入力方式とテンポを検討する。旧教材の2K風Green Releaseと0.55秒設定の継承を文書で確認。現行コードの35％減速・解放後約0.16秒の移動停止も含め、表示と待ち時間を別々に評価する。上部位置への肯定をバー方式全体の承認に広げない。現行/短いリリース/ワンタップの比較案を技術設計へ保存したが、方式変更は未決定・未実装。要件正本とG2-04は現行基準のまま保持。
