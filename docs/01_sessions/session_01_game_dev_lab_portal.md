# 📝 第1回: 複数ゲーム共通のGame Dev Labポータル

- **実施日:** 2026-08-18
- **対象フェーズ:** 教材プラットフォーム基盤
- **担当 / 執筆:** Codex

## 1. 今回のゴール（目的）

HOOPS 3Dを壊さず、その外側に今後追加する複数ゲームを一覧できる共通ポータルを作る。生徒が「遊ぶ・比べる・読み解く・つくる」の順で学べる入口を用意する。

## 2. 実装した機能・コード解説

### ① Game Dev Labトップページ

- リポジトリルートに全ゲーム共通のWebポータルを追加した。
- ゲーム一覧と4段階の学習フローを表示する。
- PC、タブレット、スマートフォンで読みやすいレスポンシブ構成にした。

### ② ゲーム情報の自動収集

- 各ゲームの `game.json` にタイトル、説明、技術、進捗、リンクを記録する。
- `import.meta.glob('../games/*/game.json')` で対象ファイルを読み込み、ゲームカードを自動生成する。

### ③ サイト全体の一括ビルド

- ルートのVite設定から、共通ポータル、HOOPS 3D、ダッシュボード、各フェーズをまとめてビルドする。
- GitHub Pagesの公開ワークフローもルートビルドに統一した。

## 3. 💡 このセッションで学んだプログラミング概念

1. **データ駆動UI:**
   - HTMLをゲーム数だけ複製せず、JSONデータから同じ形式のカードを生成すると、追加や修正が簡単になる。
2. **関心の分離:**
   - 共通ポータルと各ゲームを分けることで、全体案内の変更がゲーム本体へ影響しにくくなる。
3. **マルチページビルド:**
   - 複数のHTMLを1回のビルドに含めることで、ポータルと各教材を1つのWebサイトとして公開できる。

## 4. 🧪 動作確認（テスト方法）

1. リポジトリルートで `npm run dev` を実行する。
2. `http://localhost:5173/` にGame Dev Labが表示されることを確認する。
3. HOOPS 3Dカードからゲームと学習ダッシュボードへ移動できることを確認する。
4. `npm run build` で全ページが `dist/` に生成されることを確認する。

## 5. 次回への課題・引き継ぎ

- 2本目のゲームを追加し、`game.json` による自動登録を実際に確認する。
- 全ゲーム共通のヘッダーやパンくずリストを検討する。
- GitHub Pagesへの初回公開まで完了。次回以降は、変更をcommitしてpushすると自動公開される運用を実践する。
- 2本目のゲーム追加時に、ポータル登録・一括ビルド・自動公開までの流れを再確認する。
